Privacy Policy

Effective date: June 12, 2026

Who This Policy Is For

This policy describes how this Lagniappe instance handles information. Lagniappe is self-hosted: the person or organization operating this instance controls the Google Cloud project, Redis Cloud database, users, permissions, and optional integrations.

After installation, this instance does not contact the Lagniappe project and is not managed by a Lagniappe-hosted control plane, unless optional error reporting has been enabled.

Information the App Handles

  • Account information: names, email addresses, profile photos, login status, group membership, and permissions.
  • Workspace content: categories, projects, pages, forms, tasks, notes, comments, documents, uploaded files, generated files, and form submissions.
  • Operational information: timestamps, entity keys, cache entries, search indexes, sync state, rate-limit data, active-viewer state, and service-worker cache metadata.
  • Device and session information: browser/session cookies, timezone, user agent, referrer, and local browser state needed for login, offline behavior, and app navigation.
  • Location-related information: user-entered addresses or places in form fields, and approximate browser location only when a user chooses to share it for location-aware features.

How Information Is Used

  • To provide the workspace: showing pages, files, forms, tasks, search results, filters, and notifications.
  • To enforce access: checking authentication, permissions, group membership, page restrictions, and form restrictions.
  • To keep the app reliable: caching content, syncing open views, processing background work, rate limiting login attempts, and diagnosing errors.
  • To support optional features the operator enables, such as analytics, AI generation, OCR, or error reporting.

Where Information Is Stored and Processed

Lagniappe stores app data in the operator's configured providers, usually a Google Cloud project and Redis Cloud subscription.

  • Google Cloud Datastore: stores entities, metadata, permissions, form submissions, and app records.
  • Google Cloud Storage: stores uploaded files, generated assets, and document/file content.
  • App Engine: runs the Flask application that serves pages and handles requests.
  • Google Identity Platform: manages email/password and Google sign-in accounts and generates account-verification and password-reset codes.
  • Operator-configured email service: sends account-verification and password-reset links to users.
  • Redis Cloud: stores cache, search, filter, revisioned collaborative-document state, rate-limit, and expiring active-viewer data.
  • Optional AI/OCR providers: receive the prompts, files, images, documents, or extracted context needed for the feature being used.
  • Optional Sentry error reporting: receives diagnostic error reports only if the operator enables error reporting.

Cookies and Browser Storage

The app uses cookies for login sessions and CSRF protection. Session cookies are configured as Secure, HttpOnly, and SameSite=Lax.

The browser may also use local storage, IndexedDB, caches, and a service worker for offline support, editor state, navigation, and faster loading. Clearing browser data may sign a user out or remove offline state.

Optional Analytics and Error Reporting

Operators can enable owner-facing analytics. When analytics is on, the app may record information such as path, title, view type, referrer, navigation type, entity identifiers, and authenticated user identifiers so owners can understand how the instance is used.

Operators can separately enable owner-facing AI generation observability. While enabled, the app samples every text generation and stores a bounded summary in a separate dataset with a 30-day activity-driven retention target. Stale summaries can remain until another enabled text generation runs cleanup. Summaries contain controlled workflow/model/tier labels and aggregate request, tool, token, size, duration, validation, and error categories. They exclude prompts, generated text, tool arguments and results, error messages, file content, and user, entity, report, file, or background-job identifiers. Provider retries hidden inside the AI SDK are not visible. Owners can clear this dataset independently at any time.

Error reporting is optional. When enabled, Lagniappe disables backend Sentry default PII collection, but may still attach diagnostic request or error context such as URL, endpoint, headers, form fields, JSON payloads, or file metadata. Error reports may be sent to the configured Sentry project, which may be operated by the Lagniappe project if the default setup option is used. Reports sent to that maintainer-owned destination are governed by the Lagniappe maintainer error-reporting privacy notice.

Sharing

The app shares information with the providers needed to operate the instance, such as Google Cloud, Redis Cloud, Sentry if enabled, and AI/OCR providers if enabled. The operator may also share content with users through permissions, public pages, public files, or exported data.

Lagniappe itself does not sell personal information, and a self-hosted instance does not send normal workspace data to the Lagniappe project.

Retention and Deletion

The instance operator controls retention. Deleting records in the app removes app-managed records and linked app-managed assets, but provider backups, logs, exports, caches, browser storage, and third-party retention policies may keep copies for a period of time.

Security

Lagniappe uses server-side permission checks, CSRF protection, hardened session cookies, security headers, provider IAM, and managed cloud services. No system can promise perfect security. Operators are responsible for protecting provider accounts, local configuration files, service account credentials, Redis credentials, user access, billing settings, and backups.

User Choices and Requests

Users who want to access, correct, export, or delete information should contact the operator of this instance. The Lagniappe project cannot access or administer a self-hosted instance unless the operator has separately provided access.

Children

Lagniappe is not specifically directed to children. The operator is responsible for deciding who may use this instance and whether any additional consent, retention, or access rules apply.

Changes

The operator may update this policy as the instance configuration, providers, features, or legal requirements change.
