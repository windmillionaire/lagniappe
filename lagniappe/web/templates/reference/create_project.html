{{ subheading("What Projects Do") }}

Projects collect related tasks into one place while the tasks still live on their original pages. They are useful for recurring workflows, multi-step processes, and shared work that needs filtering.

{% call callout("tip") %} A simple project can just group tasks. Its document and model tasks are ready when the workflow needs more structure. {% endcall %}
{{ subheading("Creation Options") }}
{% call feature("Generate or Manual", icon="generate", kind="project") %} Describe a workflow and let AI draft a project, or create a simpler project manually. {% endcall %} {% call feature("Model Tasks", icon="model", kind="task") %} Model tasks are optional templates or phases. They can carry task forms so repeated work collects the same data every time. {% endcall %}
{{ subheading("Typical Flow") }} {% call step(1, "Create the project") %}

Give it a clear name and an optional description of the workflow.

{% endcall %} {% call step(2, "Add model tasks if useful") %}

Use model tasks for phases like Intake, Review, Approval, or Follow-up.

{% endcall %} {% call step(3, "Assign real tasks") %}

Tasks can be created from pages and linked back to this project for tracking.

{% endcall %}
{{ subheading("Worth Remembering") }}
  • Projects organize tasks; they do not replace the page where each task belongs.
  • Use model tasks when the same kind of work repeats often.
  • Start simple, then add structure once the project pattern is clear.
