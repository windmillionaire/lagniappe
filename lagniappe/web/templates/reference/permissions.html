{{ subheading("What This Panel Controls") }}

Permissions decide what a user or group can see, edit, create, delete, assign, or publish. Use this panel to grant access at the broad site level or to specific categories, projects, pages, and groups.

{% call callout("tip") %} Start with user groups for common roles, then use individual permissions only for exceptions. {% endcall %}
{{ subheading("Permission Levels") }}
{% call feature("View") %} Lets someone see content without changing it. {% endcall %} {% call feature("Edit") %} Lets someone update content they can access. Editing a category also lets them add pages to that category. {% endcall %} {% call feature("Create and Delete") %} Create lets someone make new containers such as categories, projects, forms, or users. Delete removes content. These are powerful permissions, especially on broad resources. {% endcall %} {% call feature("Assign and Publish") %} Assign controls task delegation. Publish controls public document visibility. {% endcall %}
{{ subheading("Broad vs Specific") }}
{% call detail("Global Permissions", kind="project") %} Apply across a whole resource area, such as models, forms, or users. They are convenient, but can grant more access than expected. {% endcall %} {% call detail("Specific Permissions", kind="page") %} Apply to one category, project, page, or user group. Use these when access should stay focused. {% endcall %}
{% call callout("warning") %} Broad permissions can hide narrower ones because the broader permission already covers the item. If a row seems missing, check whether a higher-level permission is already granting access. {% endcall %}
{{ subheading("User Types") }}
  • The primary Owner has full access, governs Administrators, and can retrieve installation configuration.
  • Additional Administrators manage ordinary site settings, content, groups, and users, but cannot alter privileged accounts or Owner-only controls.
  • Regular users get access from their groups and any individual permissions.
  • Public users are signed-in people who have not been fully created or grouped yet.
{{ subheading("Best Practices") }}
  • Grant the least access that lets the person do the work.
  • Use category edit for people who should add or maintain pages in an existing category.
  • Avoid broad create or delete permissions unless the role truly needs them.
  • After changing group membership, users may need to sign out and back in.
