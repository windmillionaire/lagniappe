Lagniappe installs into your own Google Cloud project. The setup script guides you through connecting the services it needs and deploying the app.

{% call callout("tip", False) %} Setup is the most hands-on part of using Lagniappe, but the installer explains each choice and opens the right provider pages along the way. The steps below cover what to have ready before you begin. {% endcall %} {% endcall %} {{ heading("Services Used") }} {% call card() %}
  • App Engine for hosting the app.
  • Datastore for app data.
  • Cloud Storage for uploaded files and documents.
  • Cloud Tasks for background work.
  • Document AI for OCR when enabled.
  • Vertex AI for optional AI features.
  • Google Identity Platform for sign-in and Firebase Cloud Messaging for live updates.
  • Email through Gmail, Google Workspace, or an email provider for your custom domain.
  • Redis for search, filters, and live collaboration.
  • Cloudflare optionally, to help connect a custom domain automatically.
{% endcall %} {{ heading("Prerequisites") }} {% call card() %}
{{ subheading("Accounts") }}
  • Google Cloud: an account with billing enabled
  • Email: a Gmail or Google Workspace mailbox with 2-Step Verification if you are not using a custom domain
  • Redis: a provider account
  • Cloudflare, optional: an account and temporary API token if you want automatic custom-domain setup
{{ subheading("Tools on Your Computer") }}
  • Python: version 3.12 or newer; setup can install it for you on Windows if needed
  • Git: {{ link("https://git-scm.com/downloads", "download Git") }}
  • Google Cloud CLI: {{ link("https://cloud.google.com/sdk/docs/install", "installation guide") }}
{% endcall %} {{ heading("Running the Commands") }} {% call card() %}

The dark command boxes in this guide are meant to be copied into your terminal and run from there.

On Windows, use PowerShell. On macOS or Linux, use your usual terminal.

{% call callout("note", False) %} Windows installation and recovery use setup.cmd. macOS and Linux use setup.sh. {% endcall %} {% call callout("tip", False) %} If a command says "not found" or "not recognized", check that the named tool is installed, then open a fresh terminal and try again. {% endcall %} {% endcall %} {{ heading("Installation") }} {% call card() %} {% call step(1, "Clone the repository") %}

In Windows PowerShell, use:

{{ code('$lagniappePath = Join-Path $env:LOCALAPPDATA "Lagniappe"\ngit clone https://github.com/windmillionaire/lagniappe.git $lagniappePath\nSet-Location $lagniappePath') }}

On macOS or Linux, use:

{{ code("git clone https://github.com/windmillionaire/lagniappe.git lagniappe\ncd lagniappe") }} {% endcall %} {% call step(2, "Authenticate with Google Cloud") %}

This connects the terminal to your Google account. It may open a browser and ask you to approve access.

{{ code("gcloud auth login") }} {% endcall %} {% call step(3, "Run setup") %}

This starts the guided installer. It asks a few questions, opens any provider pages you need, and explains what to copy or approve. You can review each step before setup deploys the app.

{{ code("./setup.sh") }}

In Windows PowerShell, use:

{{ code(".\\setup.cmd") }}

Setup guides you through the cloud project, sign-in, email, Redis, optional features, and deployment. If a provider requires a manual step, setup opens the right page and tells you exactly what to do.

{% call callout("tip", False) %} A new deployment can become available before Google finishes building its Datastore indexes. If Lagniappe says database setup is still finishing, wait a few minutes and refresh; no repair or redeployment is normally required. {% endcall %} {% endcall %} {% endcall %} {{ heading("Settings File") }} {% call card() %}

Setup writes your installation settings to config/files/lagniappe_settings.yaml inside your Lagniappe checkout. This file contains secrets and provider configuration, so keep it private and do not commit it to a public repository. Git ignores it, but you should still keep a secure backup.

Alongside a fresh copy of the Lagniappe source code, this is the one local file you need to recreate the same installation. It does not contain your records or uploaded files. Once the app is running, the owner can also view or download the current settings from Admin, Settings, Maintenance, then Configuration.

{% endcall %} {{ heading("Recover an Existing Installation") }} {% call card() %}

The owner download is always named lagniappe_settings.yaml, even when the installation has a custom name. On macOS or Linux, use a clean checkout and save it at the exact path below:

{{ code("git clone \ncd \nmkdir -p config/files\n# Save the owner download as:\n# config/files/lagniappe_settings.yaml\n./setup.sh") }}

In Windows PowerShell, recover into the same stable local folder:

{{ code('$lagniappePath = Join-Path $env:LOCALAPPDATA "Lagniappe"\ngit clone $lagniappePath\nSet-Location $lagniappePath\nNew-Item -ItemType Directory -Force config/files\n# Save the owner download as:\n# config/files/lagniappe_settings.yaml\n.\\setup.cmd') }}

Setup recognizes the downloaded settings file and uses it to rebuild the app without deleting or replacing its cloud data.

{% endcall %} {{ heading("Check or Repair Setup") }} {% call card() %}

The doctor command checks the installation without changing anything. It reports any files, account settings, or cloud services that need attention.

{{ code("./setup.sh doctor") }}

In Windows PowerShell, use:

{{ code(".\\setup.cmd doctor") }}

The repair command reruns setup and fixes what it can:

{{ code("./setup.sh repair") }} {{ code(".\\setup.cmd repair") }} {% endcall %} {{ heading("Cost and Maintenance") }} {% call card() %}

Light personal or small-team usage is usually inexpensive, though there is no fixed price. Cost depends on traffic, App Engine instance settings, your Redis plan, file storage, OCR, AI usage, and any changes in provider pricing.

A couple of habits keep things predictable: set Google Cloud budget alerts when you install, and check in on your Redis plan occasionally as your data grows.

Day to day, the app aims to stay out of your way. Every so often, cloud APIs, auth rules, or dependencies do shift in ways that ask for a small bit of attention, so it is worth keeping an eye on update notes.
