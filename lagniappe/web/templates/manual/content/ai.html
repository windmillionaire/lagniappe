Connect ChatGPT: app or web plugin

You can add this installation as a custom plugin in the ChatGPT desktop app or on the web. No Codex CLI or Lagniappe API key is needed.

  1. In ChatGPT, open Settings / Security and login and enable Developer mode. Availability depends on your ChatGPT account and workspace policy.
  2. Open Plugins and select the + button to add a connection. Enter {{ mcp_name }} as the name and a description such as “Connect to my Lagniappe workspace.”
  3. Under Connection, enter the MCP server URL: {{ mcp_url }}. {% if not show_connection_details %} Obtain the connection name and full MCP URL from the installation Owner and replace these examples. {% endif %} Choose OAuth if asked for an authentication method, then create the connection.
  4. Follow the sign-in prompt, sign in to your invited Lagniappe account, check the account shown, and choose Allow. ChatGPT may ask you to connect during setup or the first use.
  5. Start a new chat, select the plugin from the tools menu, and ask ChatGPT which Lagniappe account it is using. Then ask it to find a page you know you can access.

If ChatGPT asks you to reconnect later, use its Reconnect action and authorize again. Manage or remove the plugin from Plugins. To revoke its Lagniappe access, open Settings / Manage AI connections in Lagniappe.

See OpenAI's {{ link('https://developers.openai.com/plugins/deploy/connect-chatgpt', 'connection instructions') }} and {{ link('https://learn.chatgpt.com/docs/plugins', 'plugin guide') }} for current ChatGPT controls.

{% endcall %} {{ heading("Permission-Scoped Context", icon="permissions", kind="user") }} {% call card() %}

AI tools use the same permission boundaries as the rest of Lagniappe. When a user asks a question or starts an AI workflow, the app assembles context through server-side permission checks instead of handing the AI an owner-level view of the workspace.

For example, if someone is invited only to an old house category, they can ask about electricians, repairs, files, or tasks in that category. Other houses, other categories, and records they cannot view are left out of search results and AI tool responses.

{% call callout("tip", False) %} Think of AI as another reader acting on behalf of the current user, not as a separate administrator. If the user cannot see a record in Lagniappe, the AI should not receive that record as context. {% endcall %} {% endcall %} {{ heading("Privacy Model") }} {% call card() %}

Built-in AI requests go through your own Google Cloud project's Vertex AI configuration. That is a meaningfully different posture from pasting private data into a consumer chatbot account, though it is still a cloud AI service: prompts, files, and generated output are sent to Google for processing under your cloud terms and settings.

The training boundary is the important difference. Consumer AI products may use conversations to improve or train their services depending on the product, plan, and account settings. Google Cloud's managed Gemini model terms say Google will not use customer data to train or fine-tune AI/ML models without prior permission or instruction. That is stronger than relying on a consumer account toggle, but it is not the same as local-only processing.

If zero data retention matters for your installation, choose those settings intentionally. Google's guidance calls out several retention paths to review, including abuse-monitoring exceptions, request-response logging, cached data, and grounding features that may keep limited logs: {{ link("https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention", "Gemini Enterprise Agent Platform zero data retention") }}. Lagniappe setup can help disable Vertex AI caching, but that is one control rather than a blanket guarantee for every AI feature or future provider setting.

{% call callout("tip", False) %} Permissions help avoid accidental oversharing into AI calls. As with any AI output, a quick human look at generated text and extracted values is a good habit before relying on them. {% endcall %} {% endcall %} {{ heading("Cost") }} {% call card() %}

AI usage is pay-per-use through your cloud project. Text operations are usually small. Image generation and large file analysis cost more, and provider pricing can shift over time.

Budget alerts in Google Cloud are an easy safety net. If you turn on search grounding, file processing, image generation, or run large Create or Organize requests, it is worth glancing at usage a little more often.

AI is a helpful collaborator rather than an oracle. A few things to keep in mind when reviewing its output:

  • Generated schemas can look reasonable and still need a tweak or two.
  • Autofill may skip a value, or fill one in that you would rather leave blank.
  • File summaries occasionally miss a detail that matters.
  • Search-grounded answers can lean on the web rather than your own policy or records.
  • Model names, pricing, and retention settings live with the provider and can change.
