{% call card() %}

Tasks in Lagniappe live on the page they are about. A task can be a simple reminder, but the system is strongest when tasks repeat, collect structured information, and leave behind history.

It is less a kanban-first project manager and more an operational log: what needs doing, what it belongs to, who did it, and what happened each time.

{% endcall %} {{ heading("Tasks Live on Pages", icon="page", kind="page") }} {% call card() %}

A task is attached to a page: a property, person, vehicle, client, appliance, website, or whatever else you track. Opening the page shows the document, structured data, files, notes, and tasks in one place.

{% call callout("tip", False) %} The page is the thing. The task is work related to that thing. Projects can aggregate tasks later, but tasks do not lose their page context. {% endcall %} {% endcall %} {{ heading("Completion and History", icon="tasks", kind="task") }} {% call card() %}

Completing a task records who completed it and when. If the task has a form, the entered values are part of the completion record.

When a completed task is reset for the next cycle, the previous completion becomes a read-only history entry and the task is ready to be filled out again.

This works well for maintenance logs, inspections, recurring reports, medical or pet visits, document renewals, and other work where the record matters as much as the reminder.

{% endcall %} {{ heading("Scheduling") }} {% call card() %}

Tasks can have manual due dates or recurring schedules:

  • Recurring: every N days, weeks, months, or years.
  • Scheduled: calendar rules such as weekdays, month days, or yearly dates.
  • AI-generated: natural language converted into a structured schedule.

Scheduled tasks can automatically set the next due date and reset after completion. You can also postpone tasks without deleting the original due date context.

{% endcall %} {{ heading("Assignment") }} {% call card() %}

Tasks can be assigned to users. Assignment controls routing and accountability; visibility still comes from the page, form, and project permissions. An unassigned task remains visible to users who can see its page.

{% endcall %} {{ heading("Projects and Templates", icon="project", kind="project") }} {% call card() %}

Projects track a type of work across many pages. A project can define task templates, and each template can have its own form. Tasks created from a template still live on their pages, but the project gives you a cross-page view.

Example: an "Annual Maintenance" project can show HVAC, roof, and pest tasks across every property while each task stays attached to the property page where it belongs.

{% endcall %} {{ heading("Good to Know") }} {% call card() %}
  • If you only need disposable checklist items, this model may feel a touch heavier than you need.
  • For boards, sprints, dependencies, burndown charts, or time tracking, a dedicated project-management tool is a better home.
  • Task history pays off most when forms and completion habits are designed with a little intention up front.
  • Assigning a task does not on its own grant access; the assignee still needs to be able to see the page or task context.
