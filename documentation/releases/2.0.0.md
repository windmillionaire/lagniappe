# Version 2.0.0

## Required post-upgrade maintenance

Finish the software upgrade and deployment first. Setup does not run application
data migrations. Then sign in as the Owner and open **Admin → Site Settings →
Maintenance**:

1. Select **Apply Updates** to run the pending migrations, including **FIL-001:
   Single-owner Files**, **FIL-002: File Page ancestry**, **RST-001: Materialized
   local restrictions**, and **RST-002: Canonical restriction groups**.
2. Resolve any reported failures and rerun **Apply Updates** until it completes
   without failures. Files with conflicting or missing Page/Task owners and
   restrictions referencing missing groups require repair; the migration leaves
   those rows unchanged and remains incomplete until they are resolved.
3. Select **Refresh Cache** after the migrations finish. Keep the page open until
   the rebuild completes so search and permission indexes use the migrated data.

  written once without omitting a pending File.

  restrictions for existing Forms and Pages.

  direct access, search, filters, and attached Files, with live session refresh.

  cleaned up restriction rows and filter table borders.

- Fixed the image panel remaining visible after switching mobile sections.
- Fixed category deletion leaving its pages and attached content behind.
- Fixed completed-Task AI filter projection without changing shared filter
  expressions or the website filter path.
- Fixed preview and saved-filter results after Form permission changes.
- Added stable read-tool output schemas, selected catalog retrieval, bounded
  exact/Category-scoped Page lookup, and result permissions.
- Made external guidance selection deterministic and measurable while preserving

  submission validation errors.

  checklists for complete multi-file Organize coverage.

  completion-date language across API guidance.

- Fixed search display after Form restriction changes.
