# 11 — Approximate issue lookup and a saved answer

Operator-only. Stress relevant candidates from approximate wording, available
status/parent context, and completing Ask rather than answering only in chat.

## Preconditions and expected result

- The actor can read the existing issue also used by case 07: report progress
  remaining stuck after the ready notification. It was completed under
  **AI Reports** during round 2. Record current status/title/parent before
  comparison; do not put its exact identifier in the measured prompt.
- Find the operator-confirmed issue, state its observed current status, give a
  source-backed explanation where useful, and include a usable issue link.
  Do not substitute a loosely related task or invent completion details.
- Save the complete Ask answer in the website and return a report link. A
  correct unsaved chat answer is incomplete; no entity changes are requested.

## Targeted round 3 observation

Check whether concise purpose-first discovery gets directly to the job without
unrelated app/tool exploration. Search already supplies permission-checked
status and parent context: a detail read should fill an actual evidence gap,
not revalidate every hit. Retain useful detail reads for resolution/date claims.
Judge the full saved-answer workflow rather than search count alone.

eleven times and never submitted. Round 2 found the issue in one search and
saved it, but six discovery rounds consumed the gain. Completion boundaries
therefore differ between those historical arms. No attachments or prerequisite
